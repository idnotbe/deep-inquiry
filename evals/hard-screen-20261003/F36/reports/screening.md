## 문항과 실제 검증

이 사례는 세 개의 독립 소유 라우터가 각자의 서비스 비용을 최소화하는 원래 유한 운영 문제다. 운영자는 상태 공개 목록과 공급자 예약만 제어한다. 정확한 정보 공개가 다른 참여자의 경로 재선택을 바꾸고, 전용 경로 계약은 보호해야 할 A의 경로 비용을 바꾼다. 과거 파일럿의 비용을 새 공개 구성에 그대로 적용할 수 있는지와 실제 승인 가능한 최소 비용 계약을 함께 판단하게 했다. 연속 교통 게임의 수치를 바꾼 문항이나 공개 논문의 정답표를 사용한 사례가 아니다. 정보가 타인의 선택을 바꾼다는 외부 개념은 영감일 뿐 실제 모델 실패나 이 문항의 난도 증거가 아니다.

참가자에게는 C 원자료 (local retained evidence; not published)의 계정 목적, 소유권·입력 포트, 상태 확률, 서비스 가격, 예약 마감, 파일럿 기록, 판매자 제안을 제공했다. 저자 정답 목록이나 지배전략·비용 비교표를 제공하지 않았다. 판매자의 “정확한 무료 정보는 무시할 수 있으니 손해가 없다”는 문장은 제안자의 주장으로 표시했다.

원래 세 응답 모두 정보 공개 뒤 B/C가 경로를 다시 선택하여 A의 파일럿 비용이 유지되지 않는다는 점을 정확히 설명했다. 전체 공개·D 무예약에서는 NORMAL에 A:Y,B:X,C:X, RESTRICTED에 모두Y가 되어 A 서비스가7/2로11/4 한도를 넘는다. 세 답 모두 이를 거절하고 C만 새로 알리는 목록과 사전 D 예약을 골랐다. 해당 구성은 NORMAL D/Y/X의 서비스 합19/2, RESTRICTED 모두Y의 합31/2, 별도 예약료1/2로 기대 청구13을 달성한다. A의 기대 서비스는11/4다.

독립 채점 B는 세 답 모두 마감·실행 순서와 다른 예약 구성의 비교 근거를 충분히 풀어 쓰지 않았다는 이유로 feasibility/support에 각각1점을 줬다. A는 간결한 설명과 합법적인 승인 구성으로 충분하다고 보았다. 양쪽 모두 보완이 선택한 공개 목록·계약·승인을 바꾸지 않으며, 잘못된 관찰 전제나 명시적 거짓 보편 하한이 없다고 판단했다. 설명 점수 차이를 난도 인정 실패로 확대하거나 숨은 사고 원인을 추정하지 않았다.

B의 원래 full_pass 서술은 전체 항목 만점에 관한 설명이며, 사전 프로토콜의 보조 표시인 점수8이상·중대 오류0과 구분해 보존했다. 그 수치 조건은 양쪽 세 답 모두 충족한다. 선별의 주 기준은 동일 응답의 적격 실패이며 점수 평균이나 해당 서술을 유리하게 선택하지 않았다.

## 사전 복원·검토와 미사용 문항

두 새 원자료 전용 검토자가 저자 정답·증명·채점 기준 없이 C/H/K를 각각 복원했다. 원래 전체 보고서는 작업 메모리에 보존했다. calibration의 “다른 현재 신호 없음” 문장이 뒤에 제공되는 등록된 gateway 입력까지 부정하는 것으로 읽히지 않도록 한 문장만 범위를 명확히 했다. 이전 원자료 바이트와 전체 보고서를 보존하고 두 검토자가 변경 문장과 현재 해시를 별도로 확인했다. 정보·행동·가격 법칙은 바뀌지 않아 기존 수학 계산을 반복하지 않았다.

전체 정답·스키마·채점표·프로토콜의 첫 exact 검토 A와 별도 최종 B 모두 승인했다. B는 독립 정수 계산으로 모든8개 문자 그대로의 공개 목록×예약2개×사례3개, 총48개 계약 구성과3,740개 순수 전략,56,636개 일방 변경을 검사했다. 저자도 별도 Fraction 구현의 실제 실행과 관련 코드 검사에서 통과했다. 연속 혼합전략·조건과 독립인 상관된 난수·이력에 따른 무작위 설정의 범위는 엄격한 최적반응과 비용 혼합의 해석적 증명으로 확인했다. 유한 열거로 모든 혼합 분포를 검사했다고 주장하지 않는다.

미사용 H는 같은 목적·가격 아래 설치된 gateway의 실제 입력 범위가 공유 게시판인 구조적 대응 문항이다. A만 목록에 넣어도 모든 라우터가 현재 행을 읽는다. 최소는 모든 비어 있지 않은 목록과 D 예약,53/4이며 공개 안 함·무예약도 안전한 비최소 대안이다. 미사용 K는 비공개 gateway에 D-L9가 이미 설치된 대조 문항이다. C만 새로 알리고 추가 예약을 하지 않는 최소25/2다. K의 전체 공개·무추가구매는 A 한도를 실제로 지키지만51/4로 비최소다. C/H의 불안전 제안을 K에 옮겨 채점하지 않았다. 각 문항의 채점 기준은 해당 원자료에만 근거한다.

H/K의 실제 참가자 실행, 스킬 적용 비교는 수행하지 않았다. 정확한 합법 알고리즘과 동등 목록·혼합은 모두 허용했고 특정 정답표나 더 많은 수치 계산을 요구하지 않았다. 현재 결과는 이 C 문항이 필요한 난도 구분을 하지 못했다는 증거이며 스킬 효과의 증거가 아니다.

## 원래 실행과 보존 범위

두 독립 exact 승인이 일치한10개 입력·정답·증명·방법 파일의 원문 해시를 확인해 참가자 출력 전에 동결했다. 원자료3개는 CRLF이고, cases prompt는 보편 줄바꿈 정규화 후 마지막 줄바꿈을 생략한 텍스트다. 원자료 원문 바이트와 실제 전달 prompt를 서로 별도로 연결했으며 문자 그대로 동일한 바이트라고 주장하지 않는다.

새 중립 실행 baseline/treatment 두 개 모두 READY를 반환했다. 첫 baseline의 false context match는 기준 문맥을 생성하는 정상 기록이며 두 번째의 true 일치와 cross-arm 검증을 확인했다. 중립의 treatment는 전달 확인만 수행한 것으로 문제의 스킬 적용 점수가 아니다. 이번 중립 확인에는 로컬 검증 단언 실패나 재실행이 없었다.

동결 순서 r2/r3/r1의 원래 C 세 슬롯 모두 attempt1에서 완료했다. safe manifest·실제 delivery·원래 final·방법 노출 없음·도구 사용 없음·공통 문맥 일치·프로세스 종료·원본 보존·임시 인증 사본 제거를 확인했다. 외부 도구 연결 만료는 없었고 실제 완료 턴과 최종 메시지는 각각1개였다. 익명 R01/R02/R03으로 연결한 전체 원문을 새 빈 채점 구조에 넣고 실제 C task/rubric/anchor와 원문 바이트, 이전 사례·모델·실행 조건·호스트 정보 부재를 확인한 뒤 두 새 독립 채점자에게 전달했다. 저자 소견은 전달하지 않았다.

누적 실제 선별은32개 문제군·최종96개·문제 풀이137차례다. 이번 별도 중립2회는 문제 풀이 횟수에 넣지 않았다. 기존 F15의 형식 무효1개와 F19의 모호한 문항3개는 나머지92개 출력과 계속 구분한다. 그92개가 모두 올바른 답이라는 뜻은 아니다. 확보는0/6개이며 여섯 개 전체가 남아 있다.

원래 등급의 모든 필드·소견·검증·한계를 보존하고 공개 구조에서 복원한 JSON이 원래 받은 구조와 같음을 확인했다. 저자의 처음 큰 문서 생성 명령은 도구의 길이 제한으로 잘려 Python 구문 오류를 냈으며 어떤 파일도 쓰기 전에 실패했다. 짧은 명령으로 작성 후 validate3을 통과했다. 채점 A의 첫 계산 명령도 인용 부호 문제로 실행되지 않았으나 수정한 독립 Node 계산은 통과했다. 이 로컬 검증 실패를 참가자 실패·모델 재실행으로 계산하지 않는다.

요청 모델은 gpt-6-sol이며 실제 처리 백엔드는 호스트가 증명하지 않았다. 추론 수준은 판단 기준이 아니다. 원시 이벤트·숨은 추론·자격 증명·사설 문맥 파일을 보고서나 채점 자료에 넣지 않았다. 받은 검토·등급 보고서와 저자의 증명 요약은 보존된 대화 자료이며 원시 네이티브 인증 기록이라고 주장하지 않는다.

실행기·스킬·방법 및 이전 결과는 바꾸지 않았다. 관련 새 문항 검증을 통과했고 기존 전체153개 테스트·환경 제외6개·실패0개(실행147개 통과)의 증거를 재사용했다. 변경 없는 전체 테스트를 다시 실행하지 않았다. F32 이후 최종 산출물에 대한 두 검토 차례와 로컬 보관은 전체 자료 안정 뒤로 유보 상태이며 완료라고 주장하지 않는다. 커밋·푸시·새 문제 실행은 이 보고서 정리에 포함하지 않았다.
