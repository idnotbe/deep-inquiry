# F30 선별 결과

**제외. 원래 세 응답 모두 접수 시 장치를 고정하고 실제 장치별 사용 상태를 유지하는 유효한 구현을 제시했다. 양 독립 채점10·10·10, 객관적 결정 오류0개, 적격 실패0개다. 어려운 문제군 확보는 여전히0/6개다.**

## 원본 문제와 검증
공개 SWE-bench의 실제 기본값 정규화·캐시 수명 패치 실패를 구조적 힌트로 삼아, 허구의 두 장치 출력 서비스 코드와 제품 계약을 새로 만들었다. Django 코드나 공개 문제를 복사하지 않았으며 공개 실패를 현재 모델의 난도 증거로 쓰지 않았다.

C의 계약은 접수 완료 시 실제 장치를 확정하고, 이후 기본 장치 설정 변경에도 기존 주문의 장치를 유지한다. 같은 실제 장치에서는 미완료 작업 하나만 실행되고 다른 장치는 독립적으로 실행할 수 있다. 원래 코드는 실행 시 기본값을 정하고 None/명시적 ID를 별도 키로 저장하며 설정 변경 때 사용 상태를 지운다. 호출은 원자적으로 직렬 실행되고 작업은 호출 사이에도 살아 있으므로, 숨은 동시 호출·재시작·취소 요구는 없다.

두 독립 원자료 단독 검토자가 C/H의 수정과 제한된 K의 원래 코드 유효성을 복원했다. 두 검토자는 원본/부분 수정/완전 수정의 실제 Python 동작15개 관찰과 K를 각각 실행해 비공개 인증 기록과 일치를 확인했다. 이는 정답 검증이며 참가자 난도 증거는 아니다. 별도 최종 검토 뒤 문항·채점표·프로토콜·oracle·검증 코드·인증 기록을 동결했다. 모든 동등한 유효 구현을 허용했고, 기존 코드의 이미 고친 오류를 최종 답의 오류로 채점하지 않았다.

H는 편집 중 초안이 최종 접수 전까지 최신 기본값을 따라가다가 확정 시 장치를 고정하는 새 기록이다. K는 기본값 A 고정과 None 요청만 허용한다. 작성자·검토자는 보았으나 H/K를 참가자에게 실행하지 않았다.

## 실제 결과
세 답 모두 변경 없는 출시를 거부하고, accept에서 실제 장치를 저장하며 A/B별 지속적인 Lane 객체를 사용했다. 설정 변경은 기본값만 변경하고 장치 사용 상태를 지우지 않는다. 같은 장치 별칭의 중복 실행을 막고 finish가 정확한 상태를 해제하며, 다른 장치는 계속 사용할 수 있다.

저장된 실제 답의 코드를 실행한 행동 기록에서, 기본값 A의 주문을 접수한 뒤 기본값을 B로 바꾸고 명시적 A 주문과 새 기본값 주문을 접수하면 시작 결과는 A/None/B였다. 첫 A 작업 완료 뒤 대기 주문 재시작은 A였다. 별칭과 이미 실행 중인 작업의 상태 보존 기록도 통과했다. 복구 시 첫 결합 기록을 원래 최종 코드 그대로 다시 실행해 세 답 모두 확인했다. 코드 추출 해시는 코드 블록 끝 줄바꿈을 포함하며 최종 응답 원문 해시와 구분한다.

두 새 문맥의 독립 채점자는 같은 익명 패킷만 받아 각 답의 다섯 차원에 모두2점을 주었다. 모두 주어진 계약을 만족하므로 두 답 이상에서 일치하는 적격 실패 요건을 충족하지 않는다.

## 중단 복구·증거와 한계
세 원래 슬롯은 중단 전에 이미 완료됐다. 복구 시 저장된 등급이 없어 두 새 독립 채점자(f30_resume_grader_a/b)에게 정확히 같은 원래 익명 패킷을 배정했다. 기존 등급을 바꾸거나 유리한 결과를 고른 재채점은 아니다. 모델 재실행·응답 교체·입력 및 기준 변경은 없다. 두 채점은 수동 코드 추적이며 별도 실제 코드 실행 증거와 구분한다.

동결 입력·최종 원문 해시·익명 응답 대응, 실제 입력 readback, 프로세스 종료와 임시 인증 사본 제거를 저장된 안전한 manifest와 원문으로 재확인했다. 새 중립 검증2회는 별도 보존했다. 패킷 SHA256은5a7dc4f7276b898822bb7eceeadae4f2a86bba687c4cb0afb773930a3df4cbbe다. 빈 구조에서 현재 자료만 조립하고 전달 전 조건 정보 및 이전 사례 문구를 검사한 기록을 유지한다. 복구 채점자도 해당 패킷만 받았다.

코드·스킬 변경과 전체 테스트 반복은 없었다. 기존 코드의153개 테스트, 환경 제약6개 제외, 실패0개 기록을 재사용한다. 스킬 효과 비교는 범위 밖이며 실제 처리 백엔드는 호스트가 증명하지 않았다. 추론 수준은 선정 기준이 아니다. 이 결과는 F30에서 반복적인 적격 실패를 얻지 못했다는 증거다.
