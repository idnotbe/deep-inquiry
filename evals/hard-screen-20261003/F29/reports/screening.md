# F29 선별 결과

**제외. 원래 세 응답 모두 권한과 시간 조건을 만족하는 인수인계 절차이며, 양 독립 채점10·10·10, 적격 실패0개다. 어려운 문제군은0/6개로 여전히 미확보다.**

## 원본 문제와 검증
F25에서 실제 관측된 권리 보유자·이전 방향 오류를 힌트로 삼아, 허구 서비스의 고정 작업 실행 주체와 변경되는 현재 권한을 연결하는 새 업무 기록을 만들었다. F25 문항·출력·채점 기준은 변경하거나 재사용하지 않았다. 실제 제품 API에 관한 주장은 아니다.

C는 Nora명의 Pat 제거 작업이 큐에 있는 동안 Nora→Rae 소유권 이전 및 Rae·Pat의 인수검증이 진행된다. 기본 정답은 기존 작업 취소, 예정 이전·검증, Rae명의 새 제거 작업으로 Nora와 Pat을 제거하는 절차다. 제출 ACCEPTED는 실행 SUCCESS와 구별한다.

두 원자료 단독 검토자는 추가 소유권 재이전 대안을 각각 독립 발견했다. 검증 후 잠시 Nora에게 소유권을 돌리면 기존 작업도 성공할 수 있으므로 이 대안을 허용했다. 기존 작업의 예상된 무해한 DENIED 뒤 별도 유효 작업으로 목표를 달성하는 안도 허용했다. 특정 취소·교체 순서를 강요하지 않았다. K는 현재 소유자로 실행 주체를 해석하므로 기존 작업 유지가 가능하지만, C와 같은 취소·교체도 유효해 행동 차이를 강요하지 않는 제한적 대조다.

H는 관리자와 별개인 connector 서비스 실행 주체의 저장소 권한이 바뀌는 새 맥락이다. 기존 작업 재큐잉은 옛 주체를 유지하고 새 blue 작업은 새 권한 주체를 사용한다. H의 추가 권한 부여 금지는 첫 원자료부터 있었으며 C 대안을 막으려고 추가하지 않았다. H/K는 작성자·검토자가 보았으나 참가자에게 실행하지 않았다.

첫 oracle·기준 검토에서 국소 오류 수정 예외를 v3의 '주어진 전제와 가능한 대안 집합 보존'으로 정확히 맞췄다. 별도 최종 검토는 모든 합법 대안과 정확한 입력/oracle 해시를 승인했다. 명시적인 서비스 명세가 문제를 쉽게 만들 수 있다는 두 검토자의 한계도 보존했다.

## 실제 결과
세 답 모두 기존 J-81을 이전 전에 Nora가 취소하고,09:00 소유권을 Rae에게 이전하며,09:02–09:03 Pat 접근을 유지한 채 서명된 검증을 끝낸다. 이후 Rae가 자신을 실행 주체로 하는 [Nora,Pat] 제거 작업을09:06에 실행하도록 제출하고 실제 성공·최종 접근 상태를 확인한다. 모든 단계의 실제 권한과 마감이 맞는다.

양 독립 채점은 각 답의 다섯 차원에 모두2점을 주었다. 객관적 결정 오류0개, 사전 적격 실패0개다. 답의 기존 작업 DENIED 설명은 해당 절차에서 권한을 Nora에게 되돌리지 않는 조건에서 맞으며, 모든 합법적 재이전 대안의 불가능성을 주장한 것으로 확대하지 않았다.

## 증거와 한계
원래 세 슬롯만 실행했고 재시도·대체는 없다. 동결 입력·응답 해시, 실제 입력 readback, 프로세스 종료·임시 인증 제거를 확인했다. 새 중립 검증2회도 완료했다. 코드나 스킬은 변경하지 않았으며 전체 테스트를 반복하지 않았다.

채점 자료는 빈 구조에서 현재 문항·채점표·의미 기준·익명 답변과 읽어 확인한 일반 기준만 조립했다. 전달 전 조건/모델/호스트 경로·ID와 이전 사례 잔여 문구를 검사했다. 패킷 SHA256은8c1930417b9bd88f6a8948f16de95c60fe1bddbcbf28af26a3df783e0591cd3a이다. 서로 다른 새 문맥의 두 채점자가 해당 패킷만 받았다.

이 결과는 이 문항에서 반복적인 적격 실패를 얻지 못했다는 증거다. 스킬 효과 비교는 수행하지 않았고 실제 처리 백엔드는 호스트가 증명하지 않았다. 추론 수준은 선정 기준이 아니다. 미사용 확인 문항과 대조의 성능도 주장하지 않는다.
