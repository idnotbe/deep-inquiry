## 판정 근거와 이력

최종 원본 유효성 근거는 f161-clean-semantic-audit.md와 f161-validity-acceptance.md다. 부모의 패킷 검토는 별도 f161-independent-packet-review.json에 있다. 두 채점 파일은 부모가 실제 전달 결과를 그대로 보존한 JSON이며 이 마감 작업은 채점자 원시 로그를 독립 감사하지 않았다.

Source V1의 무조건적 dispatcher 게시 문장은 H와 충돌하는 P1이었다. Source V2는 공통 조건문을 고치고 간결성만으로 부차 점수를 깎지 않도록 명시했다. 기존 11개 파일을 archive/v1에 보존했고 V2는 두 독립 원문 검토에서 승인됐다. 출처 유효성 승인과 제한된 F103/F125/F140 비교는 전체 카탈로그 독창성이나 실증 난도를 증명하지 않는다.

첫 의미 감사의 P1 사건도 보존한다. 불필요한 기억 레지스트리 출력에 과거 원본 세션 위치와 식별자가 노출됐다. 과거 세션 본문은 읽지 않았고 해당 문자열을 산출물에 복사하지 않았다. f161-semantic-audit-with-privacy-deviation.md의 기술적 VALID 결과는 최종 수락 근거가 아니다. 새 독립 감사가 원본을 다시 확인했고 참가자 재실행·대체는 없었다.

최종 감사의 P2는 과도하게 넓은 파일명 탐색 중 EPERM 오류에 무관한 과거 프로젝트 산출물 디렉터리 위치가 나타난 사건이다. 세션 로그 경로·원시 UUID·파일 내용은 아니며, 과거 산출물이나 앞선 기술 감사는 읽지 않았다. 별도 기준선 B 준비 P2는 정규식 오류가 로컬 계정명이 포함된 Python 설치 경로를 출력한 사건이다. 세션 로그·원시 UUID·비밀·보호 평문은 아니었고 이후 오류는 가렸다. 두 사건의 실제 위치를 여기 재현하지 않는다. 완벽한 부수 출력 최소화는 주장하지 않는다.

최종 감사의 네 차례 광범위 출력 요청은 자동 거절되어 실행되지 않았고 같은 허용 읽기 범위에서 축소한 출력으로 필요한 근거를 확인했다. 최종 안전 검사 한 번의 승인 시간 초과는 허용된 한 번의 재시도로 완료됐다. 이들은 참가자 재시도가 아니다. 기준선 A의 실패, 기존 감사 사건, 동결 시점의 preflight/수집/패킷 대기 상태는 수정하지 않았다. 이후 별도 수락 기록이 해당 단계의 대기만 해소한다.

## 한계와 마감 검증

초기 보호 평문은 root/native API 요청 신뢰 경계에 의존한다. private reasoning·내부 bootstrap·실제 backend/fallback·완전한 내부 격리는 미확인이고 공유 파일시스템은 격리되지 않는다. 일반 지침과 기억에는 과거 평가 메타데이터·무관한 답 정보가 포함된다. F161 답안이나 H/평가자 자료/추가 C 자료/대상 스킬 제공·호출이 없었다는 가시 증거를 수락했지만, 순수 무지침 모델이나 모든 과거 답 정보의 부재를 주장하지 않는다. 원문 생략과 불투명 참조의 한계를 보존한다. 명령 prefix 원문과 기준선 동일성은 미확인이다. 실제 단일 읽기와 전체 활동의 증거에 근거한 사례별 감사 판단이며 일반 면제가 아니다. 읽기 wrapper는 동결본에 terminal LF 하나가 더해진 것으로 의미상 허용됐지만 바이트 동일하지 않다.

manifest.json은 56개 입력을 현재 바이트·SHA-256으로 동결한다. check.mjs는 동결 입력, 원문 보존, 사전 요청과 실행 요청, 공개 기록·읽기 수신·최종 사본, 패킷과 채점, 같은 ID 합의·회계, 카탈로그 prefix/suffix를 검사한다. 실행: node temp/hard-screen-20261003/worker/F161/closure/check.mjs. 실제 결과는 verification.json, 출력 묶음은 closure/candidate.json에 고정한다. 이는 기존 독립 의미 감사를 대체하는 원시 로그 검사가 아니다.

카탈로그는 기존 121,078바이트 SHA-256 59cc3c2f2108ce23975a3a0fca81ee41028dfc568dbdd7b6876312ff33fb12cd를 확인한 뒤 동결 조각을 fs.appendFile로 단 한 번 추가한다. 기존 혼합 줄바꿈을 보존하며 prefix 전체 및 suffix의 정확한 바이트 일치를 확인한다.

현재 마감 후보는 PENDING_ROOT_FULLCHECK_AND_FRESH_REVIEW다. 부모의 최종 마감 수락을 주장하지 않는다. 이 동결 상태는 이후 별도 부모 수락이 생기더라도 당시 이력으로 남긴다. 추가 참가자·채점자 실행, 원시 세션 로그 읽기, Git·네트워크·전역 설정 변경을 하지 않았다.
