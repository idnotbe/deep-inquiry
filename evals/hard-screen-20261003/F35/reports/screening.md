# F35 선별 결과

**제외. 두 독립 채점은 모두8·10·10이며, 같은 R01 한 개만 결정 오류와 적격 실패로 확인했다. 동일 응답 최소2개라는 사전 조건에 미달한다. 확보한 어려운 문제군은 여전히0/6개다.**

## 원자료와 사전 검증

같은 일곱 자산의 기존 서비스 통과4개와 새 기본 서비스 통과5개를 연결하는 새 운영 문제다. 새 프런트엔드 등록은 기존 로컬 키를 지우며, 전환 전에 키를 보존한 보호 채널만 실패 자산의 대체 서명 서비스를 제공할 수 있다. 새 기본 서비스가 통과하면 임시 보호 채널을 돌려받고, 실패하면 채널을 계속 점유한다. 구매는 첫 전환 전에 마감되며 실패한 자산을 복구하는 다른 방식의 모듈은 마감 시점에 도착한다. 목표는 모든 자산의 등록, 이전에 정상인 네 소유자의 동시 서비스, 전체 최소 다섯 자산의 서비스를 마지막8사이클에 보장하는 최소 구매 비용이다. 중간의 연속 서비스는 요구하지 않는다.

참가자에게는 날짜·동일 자산 ID·인증서·제품 용량·전환과 기록 시각·가격·목적만 제공했다. 순증가1개가 피해 소유자도 최대1명이라는 공급자의 문장은 제안으로 표시했고 신뢰할 사실이나 참가자 지시로 취급하지 않았다. 정답 비용·정책 표·실패 수를 모두 확인한 뒤의 직접 전환 분기는 원자료에 풀이로 넣지 않았다. 로컬 키의 일반적인 외부 반출 제한과 명세된 보호 장치 전송 포트의 예외를 명확히 했다.

C의 보호 채널은 각각 독립 서명 엔진을 갖는다. 추가 채널1개를 구매해 총2개를 운용하면 최소 비용2를 달성한다. 실패 영수증 두 개가 이미 확인된 뒤에는 남은 자산이 모두 기본 서비스를 통과하므로 키를 저장하지 않고 전환해도 된다. 추가 임시 채널을 억지로 요구하지 않았다. 기존 채널1개와 비용3의 복구 모듈도 전체 목표를 달성하는 다른 합법적 방식이다. H는 추가 저장 공간이 단일 공유 서명 엔진에 연결되는 구조적 상대 문항이다. 저장 채널만 늘려서는 동시 서비스를 늘릴 수 없어 복구 모듈의 최소 비용3이 필요하다. K는 구매 전에 동일 자산의 실패 ID5·6을 알고 있어 비용0으로 완료하는 대조다. H/K는 참가자에게 실행하지 않았다.

작성자의 실제 유한 검증은 가능한 실패 짝21개에서 C의 두 완전 정책과 H의 정책, K의 한 사건을 실행했다. 별도로 실패 짝1·2의 동시 서비스 물리 한계가 모든 합법적 정책의 하한을 증명한다. 두 새 원자료 단독 검토자도 각각 독립 계산으로 C2/H3/K0을 재구성했다. 첫 전체 검토는 채점 항목이 제공되지 않은 다른 문항의 사실을 언급한 문제를 지적했다. 세 문항의 해당 항목과 공통 기준의 두 문구만 실제 문항에 제공된 사실로 좁혔다. 별도 최종 검토자는 정확한 수정본을 승인하고5,040개 활성화 순서·8개 구매·가능한 사건의1,733,760개 추적을 독립 실행했다. 이 탐색이 모든 적응 프로그램을 열거한 것은 아니며, 전체 프로그램의 하한은 별도의 물리 증명으로 뒷받침한다.

## 실제 응답과 독립 채점

세 답 모두 추가 채널1개·비용2를 구매하고 공급자의 순증가 추론을 거부했다. 다만 R01은 이전 정상 자산을 전환할 때마다 먼저 빈 채널에 키를 옮기라고 무조건 명령했다. 합법적인 실패 짝1·2에서는 첫 두 채널을 지속적으로 보존해야 하므로 세 번째 자산의 키를 넣을 빈 채널이 없다. 양 채점자는 이 실제 명령이 의무 등록을 막는다고 판단했다. 구매 비용은 그대로2를 유지하되, 실패 영수증 두 개를 확인한 뒤 남은 자산을 보호 없이 전환하도록 허가하면 모든21개 사건을 만족한다. 숨은 생각이나 계산 오류를 추정하지 않았고, 이 한 근본 오류는 실행 가능성 항목에서 한 번만 차감했다.

R02는 두 채널이 차면 인증서의 두 실패를 모두 확인했으므로 남은 자산이 통과한다고 명시했다. 보호 없이 전환한다는 문장이 더 직접적일 수 있지만 두 채점자는 이 문장을 실행 분기로 인정했다. 모호한 더 엄격한 해석을 골라 추가 실패로 만들지 않았다. R03은 실패 두 개가 확인된 뒤 키 이동을 생략한다는 예외를 직접 명시했다. 두 답은 모두 모든 사건에서 실행 가능하고 최소 비용을 증명한다.

두 채점자는 각각 익명 패킷만 읽고 독립적인 메모리 내 계산으로21개 사건과 실행 분기를 확인했다. R01의 무조건 명령은 세 합법적 실패 짝1·2, 1·3, 2·3에서 막힌다. 이 사건 수를 확률로 해석하지 않았다. 두 채점의 원래 점수·설명·관찰된 주장·문제 법칙·완전한 수정 정책·결정 변경 및 해석 한계를 그대로 보존했다. 적격 실패는 같은 R01 한 개라 제외하며, 전 응답 실패 때 요구되는 추가 타당성 검토는 발생하지 않았다. 재채점·응답 교체·사후 기준 변경은 없다.

## 전달 증거와 한계

정확한 입력을 고정한 뒤 새 중립 확인2회와 원래 C 세션3개를 각각 첫 시도에서 실행했다. 외부 전송 만료·모델 재실행·도구 시도는 없다. 실제 전달 본문, 최종 원문 해시, 공통 문맥 일치, 스킬 미노출, 원본 보존, 프로세스 종료와 임시 인증 사본 제거를 확인했다. 빈 구조에서 현재 C문항·해당 채점표·고정된 의미 기준·직접 읽은 일반 규칙·익명 답변만 조립한 패킷의 SHA256은eff504260635dc583af9be5bb17dbd4b81dbcfb1244a7634cf8d2a343e32dbdf다. 작성자의 사후 발견이나 실행 조건은 채점자에게 전달하지 않았다.

원자료 C는 LF, H/K는 CRLF 줄바꿈을 사용한다. 줄바꿈을 통일하고 마지막 줄바꿈을 제외한 텍스트가 JSON의 실제 문항과 같으며, 원자료 파일 자체와 전달한 JSON·본문의 정확한 해시는 각각 보존했다. 원자료 파일과 전달 문자열의 바이트가 그대로 동일하다고 주장하지 않는다. 최초 프로토콜의 수정 전 두 필드를 복원한 파일은 이미 기록한 최초 해시와 일치하지만 독립적인 과거 원본 인증은 아니다. 최초 검토와 채점표 원본은 별도로 보존했으며 LF만으로 처음 복원한 로컬 검증 실패도 기록했다. 검토자의 UV/Python 접근 제한과 작성자의 성공한 실제 실행은 구분했다.

두 로컬 보고 검증도 정정했다. 첫 새 중립 실행은 공통 문맥을 처음 만들기 때문에 기존 문맥 일치 표시가false이고 다음 실행은true다. 처음부터 모두true라고 요구한 로컬 검증은 잘못된 조건이었으며 같은 원래 두 출력으로 확인 조건만 고쳤다. 또한 최초 진행 보고의 모델 차례136에는 별도 중립2회를 잘못 더했다. 실제 세 슬롯마다 완료 차례1개와 최종 출력1개를 안전한 사건 수와 turn ID로 확인하여 기존131+3인134로 정정했다. 원래 잘못된 보고 기록도 따로 보존했고 참가자 원문·패킷·채점·입력은 바꾸지 않았다.

현재 누적31개 실제 문제군·최종 출력93개·문제 풀이 모델 차례134개다. 중립 확인은 별도로 기록한다. 이전 형식 무효1개와 문항 모호성3개는 그대로 분리한다. 이번 한 응답의 실제 실행 실패는 근거로 남지만 반복 실패 조건을 만족하는 문제군은 여전히0/6개다. 스킬 효과 비교는 수행하지 않았다. 실행기·스킬 변경이나 새 전체 테스트는 없고 기존153개 테스트 중 환경 제약6개 제외·실패0개 기록을 재사용했다. 실제 처리 백엔드는 확인되지 않았으며 추론 수준은 고려하지 않는다.
