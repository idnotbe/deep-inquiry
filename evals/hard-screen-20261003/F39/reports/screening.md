# F39 실제 난도 선별 결과 — 제외

**원래 세 응답 모두 올바른 최적 시험·교체 정책을 제시했다. 두 독립 채점은 각각10·10·10이며 객관적 결정 오류와 적격 실패는 양쪽 모두0개다. 동일 응답 두 개 이상에서 양쪽이 적격 실패를 확인해야 하는 동결 기준을 충족하지 못해 F39를 제외한다. 확보0/6개, 여섯 문제군이 모두 남아 있다.**

이는 F39C가 이번 난도 선별에 충분히 어렵지 않았다는 실제 증거다. 스킬이 유용하거나 무용하다는 증거는 아니다. 확인 문항 H, 대조 K, 점수화한 스킬 적용 조건은 실행하지 않았다. 최종 산출물의 독립 검토와 로컬 보관은 전체 자료 안정 뒤로 유보되어 있다. 실행 전 검토와 작성자의 확인을 그 최종 승인으로 보고하지 않는다.

## 문항과 사전 타당성

같은 장비의 정상 부하 기록을 세 설치 구조가 모두 설명하지만, 냉각·릴레이·공통 입력의 의존 관계에 따라 최종 서비스에 필요한 교체 부품이 다르다. 현재 가능한18개 시험 조작은 실제 노드 방정식을 임시로 바꾸며 매 프레임 뒤 원래 상태로 돌아간다. 영구 교체 부품은 시험 뒤 도착하여 납품 시점에 설치된다. 목표는 모든 기록상 가능한 설치 구조에서 납품을 보장하고 사전 확률에 따른 기대 청구를 최소화하는 것이다. 최악 청구 최소화나 원인 이름의 완전 식별을 숨은 요건으로 추가하지 않았다.

원문만 받은 새 검토자 두 명이 세 문항을 각각 복원하여 모두 원문 충분성 APPROVE를 반환했다. 공급업체 제안 Q-610/Q-611의 승인 수정과 Q-612의 설명 수정은 원문 수정 요구가 아니다. 새 첫 전체 검토 A와 별도의 최종 전체 검토 B도 정확히 같은10개 파일을 수정 없이 APPROVE했다. 현재 문항에 실제 제공된 사실만 채점하고 모든 합법적 동등 정책·완전한 계산 절차를 인정했다.

선택한 비공개 원본의 실제 Fraction 계산은18개 조작·4개 교체 집합·적응형 결정 정책을 확인했다. 일반 원문으로 작성하면서 그 변경 없는 실행 증거를 재사용했다. 조기 주문의 지연 가능성, 전체 조작에서의 H 관측 동등성, 독립 무작위 정책의 범위는 별도 해석적 증명으로 구분했다. 원자료 A는 독립 Fraction 계산, B는 Python을 사용할 수 없어 파일 없는 JavaScript 계산을 수행했다. 전체 검토 A/B는 독립 JavaScript 물리 상태·교체·청구 확인을 수행했고 작성자의 DP나 전체 기존 테스트를 다시 실행하지 않았다. 이것들은 모델 난도 증거가 아니다.

미사용 H는 실제 현재 센서가 R만 읽는 구조다. V-18/V-24가 모든18개 시험에서 구별되지 않아도 기록에 맞는 안전한 교체가 가능하며 최적 기대 청구18/5다. 미사용 K는 무료 현재 설치 식별기가 이미 V-11을 읽었으므로 냉각 교체만 승인하는2가 최적이다. K에서는 공급업체의 과거 동시 발생 설명이 부적절해도 실제 권고는 올바르다. 이 사실을 C 채점에 섞지 않았다.

## 실제 실행과 독립 판정

동결 뒤 새 중립 실행 두 번을 별도 수행했다. 두 응답은 정확히 READY였고 두 번째 실행에서 실제 공통 문맥의 동일성을 확인했다. 첫 중립 실행의 일치값 false는 기준 문맥을 처음 만드는 단계이며, 실패나 문제 실행으로 집계하지 않는다.

원래 순서 r2→r3→r1의 F39C 스킬 없는 세 슬롯이 모두 attempt1에서 완료됐다. 각 슬롯의 실제 완료 문제 차례1개·최종 응답1개를 안전한 이벤트 메타데이터로 확인했다. 전송 대기 종료, 결과 재실행, 교체, 재채점은 없다. 입력 전달·최종 바이트·공통 문맥·소스 보존·프로세스 종료·복사된 인증 자료의 임시 폴더 정리 확인이 모두 통과했다. 스킬 본문·참조의 자동 확장과 도구 사용은 없었다. 원시 이벤트·숨은 추론·인증 내용·프로필은 읽거나 보고서로 내보내지 않았다.

R01/R02는 L=0에서 HIGH를 사용하는 합법적 반대 방향 시험으로 설치 구조를 구별했다. R03은 L=1에서 LOW를 사용하는 정책을 제시했다. 세 응답 모두 구조별 냉각·릴레이·양쪽 교체, 주문 마감과 서비스 부하, 기대 청구27/10과 하한 근거를 제시하고 공급업체의 동시 발생에서 방향을 추론한 제안을 거절했다. 작성자의 예시 시험과 다르다는 이유로 감점하지 않았다.

새 익명 묶음은 빈 구조에서 현재 과제·현재 C 채점표·동결 실패 근거·변경 없는 일반 규칙·세 실제 답만 조립했다. 조건·모델·호스트·이전 답·전체 비공개 프로토콜·작성자나 부모의 답 해석은 전달하지 않았다. 새로운 독립 채점자 두 명은 그 묶음만 받았고 서로의 결과를 보지 않았다. 두 원래 JSON을 전체 그대로 보존했다.

B는 초기화·무작위 정책·조기 주문을 따로 설명하지 않은 점과 R03의 명시적인4 청구 대안 계산 누락을 한계로 남겼다. 합법적 완전 정책과 충분한 하한이 있으므로 이를 거짓 전제나 결정 변경 실패로 확대하지 않았다. R03의 첫 문장 'two-slot diagnostic plan'은 이어지는 분기표의 조건부 계속과 함께 읽었으며 불필요한 두 번째 시험을 강제한다고 추정하지 않았다. 채점 정정이나 교체는 없었다.

동일 ID의 적격 실패 교집합은 공집합이다. 점수상 완전 통과3/3은 보조 결과이며 제외의 핵심은 양쪽에서 공동 확인된 적격 실패0개다. 세 응답 모두 적격 실패인 경우의 추가 타당성 검토 조건은 발생하지 않았다.

## 집계와 남은 범위

직전34개 문제군·102개 최종 답·143개 문제 차례에 실제 이번3개 답·3개 문제 차례를 더해 **35개 문제군·105개 최종 답·146개 문제 차례**다. 중립2회는 별도이며 문제 차례 증가0개다. 이전 형식 무효·문항 모호성·원래 점수와 선별 기준은 바꾸지 않았다. 어려운 문제군은0/6개, 아직 여섯 개가 필요하다.

기존 생산자 코드의 전체153개 테스트 중147개 통과·환경 제약6개 건너뜀·실패0개 증거는 같은 생산자 파일 해시에 연결해 재사용했다. 새 전체 테스트나 변경 없는 수학 계산은 반복하지 않았다. 이번 스키마 검증3개와 입력·등급·해시 연결의 변경 영향 확인은 통과했다. 스킬·실행기·방법론은 수정하지 않았고 저장소 보관·푸시도 하지 않았다.

요청 모델은 Sol이며 실제 처리 백엔드는 호스트가 증명하지 않아 미확인 상태로 별도 보고한다. 추론 수준은 난도·판정·중단의 고려 사항이 아니다. 이 문제는 닫힌 가상 결정론적 장비 계약이며 실제 현장 설치를 수행한 증거가 아니다. 독립 실행 전 검토와 작성자의 보고서 확인은 최종 산출물의 독립 승인과 구분한다.

사전 작성의 긴 heredoc 전송 잘림은 실행·쓰기 전에 SyntaxError로 끝났고 더 짧은 작성 명령으로 처리했다. 일반 채점 규칙 필드의 이름을 잘못 골라 생긴 KeyError도 읽기 단계에서 쓰기 전에 끝났다. 실제 selection_rules만 복원했으며 이전 답은 출력하거나 채점자에게 전달하지 않았다. 두 사건은 원래 문제 실행 실패나 결과 재실행이 아니다.
