# F76 — 설정에 따라 달라지는 관측과 반복 제어

**EXCLUDED_NOT_HARD.** 세 원래 답변 모두 끝나지 않는 제어기를 거절하고, 같은 300개를 한 번씩 완료하여 200개를 통과시키는 합법적 대안을 시각4에 제시했다. 두 독립 최초 채점 모두 10·10·10, 객관적 결정 오류0개·적격 실패0개·공동 적격 ID 없음이다. 이번 선별에서 유지할 어려운 문제군을 추가하지 못했으며 확보는 **0/6**, 전체 목표는 미완료다. 공개 자료는 준비되었고 ROOT FINAL 결합 검토를 기다린다.

원래 답변 목록 (local retained evidence; not published), A FIRST 원문 (local retained evidence; not published), B FIRST 원문 (local retained evidence; not published), [구조화한 채점](../grades-summary.json), [공개 증거](../evidence.json), [상태](../status.json)를 함께 보존했다. 답변과 두 FIRST는 원래 바이트 그대로 복사했다. 두 새 채점자는 같은 C-only packet만 독립적으로 읽었으며, 두 완전한 FIRST를 저장한 뒤에만 결과를 합치고 반복 번호 매핑을 열었다. 재채점·유리한 결과 선택·평균을 통한 판정 변경은 없다.

이 문제에서는 진단 설정 자체가 다음 표시값을 바꾼다. D는 p를, W는 p OR q를 표시한다. 현재 W/1로 선택된 집단은 01·10·11 각100개다. 제안된 반복 lookup은 01을 W/1→D/0→W/1로 계속 이동시켜 COMMIT하지 못한다. 별도의 전체 모집단 무작위 calibration 수치는 참이지만, 같은 숫자의 표시가 같은 제조 유형 집단을 뜻하거나 반복 제어가 끝난다는 결론은 주지 않는다.

세 답은 모두 D에서 얻은 읽기를 바탕으로 최종 경로를 배정한 뒤 COMMIT했다. D/0인 01은 W에서, D/1 중 10은 D에서 통과하여 총200개가 통과한다. 11은 어느 경로에서도 통과하지 못하지만 허용된 실패이며, 이 유형도 필수 COMMIT을 받는다. 전체300개 완료와 최소200개 통과를 구분했고 1+1+2=4분으로 기한8을 지켰다. R02의 calibration 설명은 압축되어 있으나 두 FIRST 모두 실제 순환과 실행 대안이 정확하다고 판정했다. 특정 D-reading recipe, 명시적 memory 문장, 인과 용어, calibration 전 셀 설명, 최대성 증명이나 분기·단어 수를 요구하지 않았다. 모든 완전한 합법적 동등 작업을 인정한다.

V2/V3와 generic 분류 기준은 바꾸지 않았다. 객관적 오류, 공개 근거로 성립하는 적격 실패, 다섯 보조 점수는 별개다. 유지에는 두 독립 채점자가 최소 두 개의 **같은** 원래 ID를 적격으로 판단해야 하지만 이번 공동 집합은 비어 있다. 세 개 모두 적격일 때의 추가 독립 유효성 감사는 발동하지 않는다. 이번 세 정답이 모든 관련 문제의 보편적 쉬움이나 스킬 효과를 증명하지는 않는다.

실행 전 두 원자료 FIRST와 같은 두 독자의 정합성 FIRST를 보존했으며 원문·목표·채점 표현 수정은0이다. 새 READY 중립 두 차례와 원래 C 순서2·3·1의 세 차례는 모두 attempt1에서 완료했다. 준비 재시도0, 각 원래 문제 차례1개·최종 답1개이며 실제 입력·문맥·미노출·격리·소스 보존·무도구·모델 프로세스 및 인증 복사본 정리 guard가 통과했다. PID-before-GO와 동일 소유 원래 producer 종료0을 확인했고, 중립 완료 후 새 common reference만 원래 계획에 연결했다. 원래 답변 해석과 packet 생성은 ROOT SAFE 승인 뒤에 이루어졌다.

두 절차 한계를 구분해 보존했다. 작성 단계 단일 검사는 마지막 경로 key 조회에서 실패하여 원래 aggregate FAIL을 유지한다. 앞선 suite1·plans2·inputs4 실행 뒤 미완료 마지막 hash bookkeeping만 ROOT의 좁은 승인으로 별도 정합화했으며 검사를 재실행하거나 원래 기록을 PASS로 바꾸지 않았다. 또한 이미 관측한 원래 tool 결과를 저장하는 별도 메타데이터 작성 호출은 timeout으로 종료 상태가 **UNKNOWN**이다. 완성된 파일과 후속 읽기는 그 작성 프로세스 종료의 증명이 아니다. 실제 원래 producer 종료와 모델 정리는 별도 증거로 PASS이며 ROOT SAFE가 이를 구분하여 승인했다. 해당 작성 호출의 재시도·프로세스 probe는 하지 않았다.

확인 하한은 시도 문제군63개·최종 문제 답184개·완료 문제 차례240개이며 F46/F51의 실제 기여는 UNKNOWN이다. 이 숫자가 모든 과거 답의 프로토콜 유효성을 뜻하지 않는다. 중립 READY 두 차례는 문제 집계에 더하지 않았다.
