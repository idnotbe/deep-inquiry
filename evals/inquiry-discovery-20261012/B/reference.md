# 방향 B 참고 판단과 제작 기록

저자 작성·자체 확인 단계다. 독립 검토, 동결, 참가자 실행과 난도 확인은 아직 하지 않았다. 질문은 합성 업무 사례이며 외부 사실을 필요로 하지 않는다.

## 중심 판단

문제는 빈 시간의 존재를 모르는 데만 있지 않다. 예약 팀은 미사용을 알고도 이용권을 유지하고, 담당자는 취소 전 재배정할 수 없다. 자발적 취소에 기대는 현황 화면·알림만으로 이 규칙은 바뀌지 않는다. 사용 권한이 언제 확정되고 언제 풀리는지, 풀린 칸이 누구에게 언제 넘어가는지를 정하는 운영이 필요하다. 기존 도구와 담당자 권한으로 가능하다.

하나의 충분한 안은 기존의 이른 예약은 허용하되, 다음날 사용할 시료·담당자를 오후 5시에 확인하고 준비되지 않은 임시 예약을 해제하여 준비 가능한 대기 요청에 확정 배정하는 것이다. 오후 5시 검토 직후 다음날 칸을 알려주면 제공된 90분 준비 조건을 충족할 수 있다. 확정된 연속 두 칸의 개발 시험은 유지한다. 전날 확인 시점을 적절히 앞당기는 안도 가능하다.

이 예시와 같은 제도를 요구하지 않는다. 담당자가 준비 여부를 확인하여 직접 해제·재배정하는 방식, 임시 예약의 수나 보유 기간을 제한하면서 사용하지 못하는 칸을 조기에 회수하는 방식, 확정 작업을 보호한 범위에서 대기 요청용 칸을 운영하는 방식도 근거와 실행 조건이 맞으면 인정한다. 화면·알림을 함께 도입해도 된다. 기능 이름보다 실제로 이용권과 배정 시점이 바뀌는지를 본다. 여러 제도를 한꺼번에 도입하거나 창의적인 명칭을 붙일 필요는 없다.

연속 시험까지 전부 하루 전 예약으로 바꾸면 외부 장비 준비를 할 수 없다. 확정된 작업의 선착순 이용권을 유지하는 통상 운영은 이 집단에서 타당하다. 실제로 네 칸 모두 사용한 날의 긴급 요청 2건은 이번 권한 안에서 모두 수용할 수 없다. 당일 예기치 못한 공백도 반드시 메울 수 있는 것은 아니다. 단순 전체 사용률보다, 준비 가능한 긴급 요청이 사전에 알려진 미사용 예약 때문에 밀렸는지와 확정 개발 시험이 유지됐는지를 확인하면 충분하다. 소규모 2주 관찰로 일반적인 효과 크기를 단정하지 않는다.

## 중요한 오류와 허용 범위

- **배정 규칙을 그대로 둔 채 정보 제공만으로 해결됐다고 판단:** 자발적 취소가 늦고 팀들이 상황을 이미 안다는 기록, 취소 전 재배정 불가 규칙에 반한다. 네 긴급 건과 같은 상황에서 빈 칸이 있어도 준비 시간이 사라지는 원인이 남는다. 단순히 화면을 제안했다는 이유로 실패가 아니며, 담당자의 실질적 조기 회수·배정이 포함됐는지 확인한다.
- **모든 예약을 직전 예약으로 바꾸거나 긴급 요청에 무조건 우선권 부여:** 사전 준비가 필요한 확정 연속 시험 또는 확정 작업 보호 조건을 침해한다. 임시 예약에만 적용하는 제한은 이 오류가 아니다.
- **시작 시각의 불참 확인·해제만으로 사전 미사용 문제까지 해결됐다고 판단:** 해당 칸을 온전히 써야 하고 준비에 90분이 필요한 반례 4건을 해결하지 못한다. 당일 사고 대응의 보조 규칙으로 쓰는 것은 타당하다.

질문에서 요구하지 않은 정교한 제재·시스템 개발·새로운 성과 지표는 필요하지 않다. 알림의 가치를 전면 부정하거나 모든 긴급 건의 성공을 보장할 필요도 없다. 짧은 실행안, 다른 타당한 배정 방식, 향후 수요의 불확실성 인정은 감점 사유가 아니다. 미언급 사항을 잘못된 의도로 추정하지 않는다. 방향 B의 핵심 실패는 실제 배정을 막는 규칙을 유지하면서 표시·알림의 변경만으로 목적을 달성했다고 보는 경우다.

## 출처와 자체 확인

설계 근거는 `docs/evaluation-purpose.md`의 작동 방식 변경·운영 조건·통상 해법 허용, 승인된 `temp/hard-screen-20261003/next-goal-proposal-20261011.md`의 방향 B, `temp/inquiry-discovery-20261012/state.md`의 유한 탐색 범위다. A의 참가자 응답은 읽지 않았고 A 파일도 변경하지 않았다. 예약 취소·확정의 권한, 준비 시간, 도구 기능은 모두 질문에 명시한 합성 조건이다.

자체 확인 시나리오와 이진 판정: (1) 28개 사용 칸과 12개 미사용 칸이 총 40칸이고 미사용 원인 8+4, 긴급 미처리 원인 4+2가 일치함 — 일치. (2) 전날 해제·재배정은 초기 준비 조건 및 확정 작업 보호와 양립함 — 양립. (3) 자발적 알림만 유지하는 안과 전부 직전 예약으로 바꾸는 안 각각에 제공된 구체 반례가 있음 — 있음. (4) 여러 실행 가능한 대안과 통상 예약이 타당한 집단을 허용함 — 허용. 실제 시험실이나 참가자 성능은 시험하지 않았다.

확인 호출은 `mcp__node_repl__js`에서 두 파일의 `fs.readFile`, 파일 크기·어절 수·SHA-256 계산과 문서 자체 재열람이다. 관측 산출물은 이 `reference.md`와 같은 폴더의 `question.md` 두 파일이며, 확인 해시는 상위 담당자에게 전달한다. 위험: 임시 예약의 해제와 사전 확정이 익숙한 해법이므로 일반 답변만으로 쉽게 풀릴 가능성이 높다. 그 가능성을 난도 주장이나 추가 함정으로 바꾸지 않는다.
