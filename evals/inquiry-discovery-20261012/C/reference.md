# 방향 C 참고 판단과 제작 기록

합성 사례의 저자 작성·자체 확인 단계다. 독립 검토·동결·참가자 실행 전이며 난도나 재현되는 실패를 확인한 것이 아니다.

## 자료가 지지하는 결정

약 96%를 고객의 빠른 복구가 개선됐다는 근거로 삼아 **현재 방식과 성과 기준을 그대로 전면 확대하는 판단은 지지되지 않는다.** 변경 후에는 작업표 없는 10건이 분모에서 빠지고, 부품·기사 관련 작업표 10건은 최초 요청보다 4~8일 늦게 시작됐다. 그 10건의 작업표 기준 성공은 고객 요청 다음 날 복구를 뜻하지 않는다. 미완료 작업표를 화면이 모두 제외해서 생긴 문제로 설명해서는 안 된다. 질문은 이 작업표들을 분모에 포함한다고 명시한다.

같은 출발점인 최초 요청을 기준으로 보면 24시간 내 실제 복구는 80건에서 76건, 14일 내 복구는 98건에서 90건이다. 변경 후 10건의 미복구 중에는 취소 4건도 있다. 전체 고객의 복구가 빨라졌다고 단정할 자료가 아니다. 센터 발언과 대기 6건 중 4건의 자원 요청 지연은, 성과 기준이 작업표를 늦게 만드는 행동과 고객 대기를 함께 남길 수 있음을 뒷받침한다. 단순히 작업표 생성만 앞당기고 실제 부품 요청·기사 예약을 계속 늦추면 목적을 충족하지 못한다.

그렇다고 모든 변화가 무익하다고 단정해서도 안 된다. 설정 문제의 24시간 내 복구는 72건에서 76건으로 늘었고 반복 설명 감소도 보고됐다. 같은 분류 안의 난도 차이와 다른 관측되지 않은 영향이 있어, 정책이 악화의 전부를 일으켰다거나 해결 절차만으로 개선분 전부가 생겼다고 확정할 수는 없다. 이 불확실성은 현재 수치만으로 전면 확대를 정당화하지도 않는다.

## 실행 가능한 여러 선택

충분한 예시는 공통 해결 절차는 유지하거나 확대하되, 현 센터의 사전 상담에도 담당자와 다음 조치를 두고 부품 요청·기사 예약을 지체시키지 않도록 하는 것이다. 고객 성과는 최초 요청부터 실제 사용 재개까지로 보고, 아직 열린 요청과 취소도 함께 추적한다. 수정한 운영을 다음 달 관찰한 뒤 다른 센터 적용을 결정할 수 있다.

최초 요청 즉시 작업표를 만드는 이전 방식으로 돌아가면서 해결 절차를 유지하는 선택도 가능하다. 사전 상담을 유지하되 모든 요청이 최초 시각부터 성과·대기 관리에 포함되고 실제 후속 조치의 책임과 확인 시점을 정하는 선택도 가능하다. 이러한 수정안을 제한적으로 확대하는 것도 허용한다. 새로운 복잡한 도구나 특정 상담 시간 제한을 반드시 도입할 필요는 없다. 짧은 답이어도 무엇을 유지·변경하고 어떤 고객 결과로 재판단할지 근거가 맞으면 충분하다.

## 실질적인 실패 기준

- **잘못된 개선 판정으로 현재 운영·성과 기준을 그대로 확대:** 80%와 약 96%를 같은 고객 대기 기준의 성과로 취급하거나, 제외된 고객·늦게 시작한 시계를 무시하고 실제 복구가 개선됐다고 결론 낸다. 비교 가능한 실제 복구와 취소 기록이 반례다. 성과 화면을 업무 처리 속도의 보조 지표로 유지하는 것 자체는 오류가 아니다.
- **성과 숫자만 고치고 고객을 놓치는 조치를 충분한 해결책으로 판단:** 미등록 요청이나 취소를 계속 관찰 대상에서 빼거나, 이미 자원 요청이 누락된 사전 상담을 계속 무기한 보류한다. 조치의 명시된 운영이 실제 대기 원인을 유지할 때 적용한다. 간결해서 담당자 이름·세부 기한을 쓰지 않았다는 이유만으로 실패를 부여하지 않는다.
- 인력·재고 부족이 입증됐다고 가정해 범위 밖 증원만을 해법으로 삼는 답은 근거와 실행 가능성을 따로 검토한다. 반대로 정책의 인과 효과를 확정하지 않고 유지·수정·추가 관찰을 결합하는 답은 허용한다. 모든 항목을 폐지하거나 이례적인 대안을 내야 정답인 문제가 아니다.

방향 C의 핵심은 동일해 보이는 수치가 담당자의 행동과 기록 규칙 변화 때문에 다른 의미가 됐는지 보고 실제 권고를 바꾸는 것이다. 다른 업무 배경이라는 이유만으로 A·B와 독립적인 실패 유형이라고 주장하지 않는다.
